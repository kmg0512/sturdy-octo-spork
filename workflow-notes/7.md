## Implementation Notes: Add Status Badge (Auto-trigger test)

**Summary**
Adds a status badge to the Kanban board UI to visually surface the current auto-trigger / workflow run state for each card, backed by the existing GitHub service and workflow engine.

**Changes**

- `src/components/KanbanBoard.tsx`
  - Renders a new status badge on each card, mapped from the workflow/run status (e.g. `idle`, `running`, `success`, `failed`).
  - Badge color/label derived from a small status→style lookup; falls back to a neutral "unknown" state if no status is present.

- `electron/workflow-engine.ts`
  - Emits/exposes the run status transitions needed to drive the badge (e.g. on trigger start, completion, failure) so the renderer can subscribe rather than poll.

- `electron/ipc.ts`
  - Adds/extends an IPC channel to forward workflow status updates from the main process to the renderer for the badge to consume in real time.

- `electron/github-service.ts`
  - Supplies/normalizes the status data sourced from GitHub (e.g. check run or commit status) used as one of the inputs to the badge state.

- `electron/auto-trigger.ts` (new)
  - Encapsulates the auto-trigger logic that was being tested, producing the status events consumed above.

**Testing**
- Manually verified the badge updates on trigger start, success, and failure paths.
- Confirmed no regression to existing Kanban card rendering when status is absent.

**Follow-ups / out of scope**
- Persisting badge state across app restarts is not covered here.
- No changes to styling tokens beyond the new badge component.

## Implementation Notes: Persistence Test — Add a Config Validator

**Issue:** Persistence test: add a config validator

### Problem
The persistence layer (`electron/store.ts`) reads/writes app config to disk without validating shape or types on load. A corrupted, hand-edited, or version-mismatched config file can be loaded silently, producing `undefined`/malformed values that surface as runtime errors deep in `workflow-engine.ts` or `ipc.ts` rather than at load time.

### Approach
1. **Schema definition** — Define a validator for the persisted config shape (e.g. via `zod`, or a hand-rolled type-guard if we want to avoid a new dependency) covering every field currently read from the store: workflow settings, GitHub service credentials/config, auto-trigger rules, and any Kanban board state persisted from `KanbanBoard.tsx`.
2. **Validation on load** — In `electron/store.ts`, wrap the deserialize step so that on load the raw JSON is passed through the validator before being handed to consumers.
   - On success: return the validated/typed config as today.
   - On failure: fall back to defaults for the invalid subtree (not the whole config, to avoid wiping unrelated valid settings), and log a warning identifying which field(s) failed validation.
3. **Validation on save** — Optionally validate before writing to catch programmer errors that would otherwise persist a bad shape (defense in depth, cheap given the same validator).
4. **Migration compatibility** — If the config has a version field, ensure the validator is version-aware or run after any migration step, so old-format configs aren't flagged as invalid before they've been upgraded.

### Testing
- Add a persistence test suite (e.g. `electron/store.test.ts`) covering:
  - Valid config round-trips unchanged.
  - Missing required field → falls back to default for that field, rest of config intact.
  - Wrong type (e.g. string where boolean expected) → rejected with a clear error/log, default substituted.
  - Extra/unknown fields → ignored or stripped, not treated as fatal.
  - Empty/corrupted file (invalid JSON) → falls back to full default config without throwing.
- Verify no regression in existing store read/write tests.

### Files touched
- `electron/store.ts` — add validator invocation on load/save.
- New: validator/schema module (co-located with `store.ts` or under a `schemas/` folder).
- New: `electron/store.test.ts` (or extend existing test file if one exists).

### Out of scope
- No changes to the on-disk config format itself — this only guards against malformed data, it does not introduce a new schema version.
- No UI-facing changes; failures are handled silently with logging, not surfaced to the user in this PR.
